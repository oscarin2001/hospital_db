================================================================

Se unifico la base de datos de un hospital a partir de tres fuentes:

    Tablas: zona, especialidad, tipo_diagnostico, persona,

2. NORMALIZACION 3FN - COMO SE ELIMINO EL BUCLE
================================================================

PROBLEMA ORIGINAL:
  El esquema del Grupo 3 tenia un bucle/dependencia circular:
  
    persona --FK--> especialidad (campo id_especialidad en persona)
    personal --FK--> persona
    personal --FK--> especialidad
  
  Esto viola 3FN porque:
  - La especialidad es un atributo del ROL MEDICO (personal), no de la persona
  - Un paciente no tiene especialidad, pero la columna existia en persona
  - Generaba dependencia transitiva: persona -> especialidad (directo)
    y persona -> personal -> especialidad (indirecto) = REDUNDANCIA

SOLUCION APLICADA:
  1. Se ELIMINO id_especialidad de la tabla persona
  2. La especialidad queda SOLO en la tabla personal (donde corresponde)
  3. Se crearon tablas de rol: paciente y personal
  
  Flujo de FK limpio (sin ciclos):
  
    zona <-- persona --> (datos basicos de cualquier individuo)
                |
                +-- paciente (rol: paciente)
                |       |
                |       +-- historial_clinico
                |
                +-- personal (rol: medico/empleado)
                |       |
                |       +-- especialidad
                |       +-- cat_cargo, cat_turno, cat_estado_disponibilidad
                |
                +-- horario_medico
                +-- cita_medica (id_paciente, id_medico -> ambos persona)
                        |
                        +-- diagnostico --> tipo_diagnostico
                        |       |
                        |       +-- receta --> receta_detalle --> medicamento
                        |       +-- diagnostico_procedimiento --> procedimiento_medico
                        |
                        +-- pago --> cat_metodo_pago, cat_estado_pago

4. COMO SE ADAPTO TODO
================================================================

  PASO 1 - Esquema unificado (schema_pg.sql):
    Se tomo como base el esquema del Grupo 3 y se le agrego:
    - Los 9 catalogos del Grupo 2 (cat_genero, cat_cargo, etc.)
    - Las tablas de extension del Grupo 2 (pago, procedimiento_medico, etc.)
    - Las tablas de rol: paciente y personal (separacion 3NF)
    - Se QUITO id_especialidad de persona (movido a personal)
    - Se agregaron CHECK constraints para validacion

  PASO 2 - Carga de Grupo 3 (load_grupo3.py):
    - Lee el dump PostgreSQL DIRECTO (no pasa por SQLite)
    - Parsea los bloques COPY del dump
    - Para persona: separa id_especialidad y lo guarda aparte
    - Inserta datos con COPY FROM STDIN (rapido, nativo PG)
    - Despues crea registros en paciente/personal segun matricula:
      * matricula != NULL -> es medico -> va a personal (con especialidad)
      * matricula == NULL -> es paciente -> va a paciente
    - Tambien carga los catalogos y procedimientos/medicamentos del Grupo 2

  PASO 3 - Datos propios con Faker (populate_db_pg.py):
    - Agrega 9 especialidades nuevas (24 total)
    - Agrega 10 zonas nuevas (30 total)
    - Genera ~330 medicos nuevos (persona + personal)
    - Genera 30,000 pacientes nuevos (persona + paciente)
    - Genera 50,000 citas medicas
    - Genera diagnosticos con enfermedades reales por especialidad
    - Genera recetas, pagos e historial clinico

11. NOTAS FINALES SOBRE LA ADAPTACION (Grupo 2 y Grupo 3)
================================================================

  - Grupo 3: provee los datos originales en formato PostgreSQL (COPY). Se importaron
    las tablas base directamente y se respetaron tipos y valores originales cuando fue
    posible. Algunas columnas se transformaron para respetar la normalizacion.

  - Grupo 2: aporto los catalogos y tablas de extension (procedimientos, medicamentos,
    pagos, historial, etc.). Estos se integraron como tablas separadas y referenciadas
    por FK (sin duplicar datos entre tablas base y catalogos).

  - Resultado: esquema unificado en 3NF, sin ciclos entre `persona` y `especialidad`.
    Las transformaciones principales fueron:
      * Eliminar `id_especialidad` de `persona`.
      * Crear `personal` y `paciente` como roles (una persona puede ser paciente o personal).
      * Mantener los catalogos del Grupo 2 como tablas independientes y usar FKs.
